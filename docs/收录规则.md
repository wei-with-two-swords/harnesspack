# HarnessPack 收录规则（名单来源与退出机制）

> 一句话：**名单不自己收**。我们直接采用 awesome-dsh-plugin 的精选清单与分类，每天同步；我们只负责按仓库去重、抓 star、算榜单，并对失效仓库执行退出。

## 1. 名单来源

- 上游：<https://github.com/awesome-dsh-plugin/awesome-dsh-plugin>（CC0-1.0），站点 <https://awesome-dsh-plugin.com>，清单数据 `data/plugins/<owner>__<repo>.yml`，聚合产物 `https://awesome-dsh-plugin.com/plugins.json`。
- 收录门槛（上游定义，我们不重复评审）：可安装进 DSH（`package.json` 含 `dsh.bundle`）、真实可用代码、仓库创建满 1 天、活跃维护、描述属实。
- 提交方式：到上游仓库提 PR，**不要**给 HarnessPack 提收录 PR；上游合并后，我们下一次同步自动收录。
- 分类：沿用上游 23 个分类（ui / tools / session / workflow / usage / dev / model / memory / theme / skill / notify / fun / remote / security / browser / docs / vision / git / voice / market / identity / agi / wsl），不做二次归类。

## 2. 仓库级去重

- 上游存在子目录条目（如 `owner/repo/tree/main/packages/x`），多个条目可能指向同一个仓库。
- 我们按 `owner/repo` 归一：同一仓库只保留一条，展示名取 star 最高的条目名（去掉 `#` 子包后缀）。
- 因此站点收录数（约 1.1 万）小于上游条目数（约 1.22 万）。

## 3. 每日同步

`GitHub Actions` 每天：

1. `scripts/vendor_catalog.py` 拉取 `plugins.json`，归一为仓库级，写入 `data/catalog/latest.json`，并把新增/移除/改名写入 `data/catalog/changelog.jsonl`；
2. `scripts/build_seed.py` 由 catalog 生成 `data/plugins.seed.json`；
3. `scripts/snapshot_graphql.py` 用 GraphQL 批量抓取 star（100 仓库/请求），写入 `data/snapshots/YYYY-MM-DD.json`；
4. `scripts/validate.py` 校验后提交到 git；服务器 `git pull` + 导入。

## 4. 退出机制

| 触发 | 处理 |
| --- | --- |
| 上游删除条目 | 次日标记 `status=exited`，退出榜单，历史曲线保留、页面不 404 |
| 仓库 404 / 被删除 | 同上，`exit_reason=repo_gone` |
| 仓库 archived | 次日退出，`exit_reason=archived` |
| 90 天无 push 且 star 无净增长 | 先进入观察区（`status=watch`），再 60 天仍无变化则退出 |
| 重新被上游收录 | 恢复 `status=active`，从恢复当天重新计增量（不补历史） |

- 退出不删除数据：`stars` 历史全部保留，详情页标注「已退出榜单」。
- 退出/恢复全部写入 `changelog.jsonl` 并随 git 提交，可审计。
- 被退出后再次收录的仓库，冷却 30 天（可与上游规则叠加）。

## 5. 不做什么

- 不排名之外做质量评分；star 榜就是唯一排序依据。
- 不做「赞助进榜」：推荐位物理隔离、明确标注，不参与任何榜单与收录判定。
- 不手工调整 star 数字；异常增量只标注、不删除。
