# HarnessPack 500 收录规则（进入与退出机制）

- 版本：v1.0（2026-11-19）
- 状态：待评审
- 上游：[需求分析](需求分析.md) FR-D1 / [设计文档](../设计文档.md) §0
- 一句话：**500 是容量上限，不是终身席位**。进入靠「资格 + 评审」，退出靠「失效 + 挑战」，全程留痕公示；退出不销毁历史。

---

## 0. 原则

1. **宁缺毋滥**：名单不足 500 时保持空缺，不用低质量仓库凑数。
2. **单一品类**：只收可安装进 DeepSeek Harness（DSH）的插件（package.json 含 `dsh.bundle` 或 `dsh.client`）；不收 DSH 本体、桌面客户端/启动器、应用、教程、聚合列表与跨 harness 产品。
3. **榜单稳定优先**：换人要可预期（有节奏、有上限），否则押注与曲线叙事都会失真。
4. **可解释**：每条收录/退出都能追溯到规则与数据（star、活跃度、仓库状态），不接受「我觉得行」。
5. **作者友好**：提供自荐入口、申诉通道与自愿退出；误判可恢复。
6. **透明**：所有变更写 changelog 并公示；seed 的 git 历史即审计日志。

---

## 1. 容量与节奏

| 项 | 规则 |
|---|---|
| 展示容量 | 500 条（在册 `status=active`） |
| 观察区 | 最多 30 条（被替换或待复核，保留曲线、不进榜） |
| 候选池 | 不限（提名未通过或名额已满的仓库） |
| 准入评审 | 每月第一个周一（UTC）一次，集中处理提名 |
| 挑战者替换 | 每周一结算后一次，**每期最多 10 席**（≤2%） |
| 紧急退出 | 违规、删库、作者申请：随时生效 |
| 冻结期 | 周结算周期内（UTC 周一 00:00 至周日 24:00）不换人，保证押注公平 |

---

## 2. 准入资格

### 2.1 硬性条件（缺一不可）

1. **公开仓库**：GitHub 可匿名 `GET /repos/{owner}/{repo}` 返回 200；非 fork（官方迁移/改名除外）。
2. **品类匹配**：仓库的主要目的是发布 DeepSeek Harness 插件，README 写清安装方式（`dsh plugin add` 或插件市场），且 package.json 有 `dsh.bundle` / `dsh.client` 块。
3. **可用性**：近 180 天有 commit 或 release；README 非空；有开源 LICENSE。
4. **规模门槛**：star ≥ 30（首版阈值，可在 `config.py` 调整）；近 30 天 star 有非零变化，或总量已达标。
5. **不在排除清单**：
   - DSH 本体：deepseek-ai/deepseek-harness；
   - 桌面客户端与启动器（如 dsh-desktop、dsh-Go 这类壳应用）；
   - 纯清单/导航站（dsh-top100、dshfind、dsh-plugin-radar 等）与 awesome / 资源列表、纯教程、内容农场；
   - 跨 harness 应用本体（同时服务多家 harness 的应用，而非 DSH 插件），以及「顺带提供 skill」的产品仓库；
   - 破甲 / 越狱 / 违规类插件；镜像、聚合、换皮、空壳仓库。
6. **唯一性**：同一仓库只收一次；同一项目的子目录按主仓一条；同名变体不收。

### 2.2 加分项（同分排序用，不影响硬性资格）

- 官方/知名组织背书；近期有 release；有真实使用案例或演示；文档完整；有 CI/测试。

### 2.3 提名渠道

- **作者自荐**：GitHub Issue 模板（仓库名、一句话说明、安装方式）。
- **社区推荐**：同一 issue 模板，注明推荐理由。
- **自动发现**：GitHub topic（`dsh-plugin`）、dsh-plugin-radar 索引、star 增速异动巡榜。
- 自荐不优待：所有来源进同一队列，按资格分排序。

---

## 3. 评审流程（每个提名 7 天内出结果）

1. **自动预检**（脚本）：存在性/公开/非 fork/star/活跃/重复/排除清单 → 输出通过或拒绝原因。
2. **人工复核**（≤10 分钟）：类别、harness、收录理由、与既有条目是否重复。
3. **决策记录**：`approved / rejected / need-info`，写入 PR 评论与 seed 变更。
4. **合并生效**：下一次快照（UTC 00:10）开始采集；**收录日 = 首个有效快照日**（Day 0），不补历史。
5. **名额已满**：进入候选池排队，等挑战者机制或下月评审。

---

## 4. 退出机制

### 4.1 触发条件（任一命中）

| 编号 | 条件 | 处理 |
|---|---|---|
| E1 | 仓库删除/转私有（404 连续 7 天）或归档（archived 连续 14 天） | 退出，标记 `repo_gone` |
| E2 | 定位改变：不再可安装进 DSH（转为应用/课程/桌面客户端） | 退出 |
| E3 | 长期失活：连续 90 天无 commit/release 且 star 无净增长 | 先入观察区；再 60 天无变化退出 |
| E4 | 违规：确认刷 star、恶意代码、侵权投诉成立 | **立即退出**并公示证据链接 |
| E5 | 挑战者替换（见 §5） | 退出并进入观察区 |
| E6 | 作者申请自愿退出 | 立即下架，停止更新 |

> 注：star 注水本身**不**触发退出，先标记异常、降含金量分（见需求分析 FR-D6）；只有确认违规才走 E4。归档后重新活跃的仓库可在 90 天后挑战回归。

### 4.2 退出后的数据处理

- **榜单**：退出次日起不参与任何榜单与押注；当周已下注按周初名单结算，不追溯。
- **历史**：保留历史 star 与曲线，详情页显示「已移出收录 + 原因 + 日期」，不再更新，页面不 404。
- **展示**：总榜/竞速榜/新秀榜排除；`/about/changelog` 公示。
- **重新收录**：冷却 30 天；同一仓库 12 个月内最多 2 次进出。
- **删除权**：作者可要求删除全部数据；删除后页面 410，榜单移除。

---

## 5. 挑战者替换（保持名单活力）

- **综合分** = 0.5 × 近 30 天 star 增速（分位）+ 0.3 × 活跃度 + 0.2 × 相关性与文档质量（人工 1–5 分归一化）。
- **比较对象**：候选池榜首 vs 在册名单「近 90 天综合分」末位。
- **规则**：挑战者分 > 末位者 → 替换；每期最多 10 席；被替换者进观察区，下期可挑战回来。
- **时机**：周一结算完成后 30 分钟内执行，随后公示。
- **约束**：新收录满 30 天才能被挑战（避免刚上榜就被挤掉）。

---

## 6. 与押注的关系

- 押注池 = 每周一 00:00 UTC 的在册名单快照。
- 当周内发生退出/替换，不影响已下注（按周初名单结算）。
- 新收录条目**当周不可押**（至少积累 7 天数据），避免信息不对称。

---

## 7. 公示与申诉

- **changelog**：`data/changelog.jsonl`，字段 `date, slug, action(enter|exit|replace|recover|remove), reason, evidence_url`；按月归档；前端 `/about/changelog` 展示最近 50 条。
- **申诉**：GitHub Issue 模板，7 天内答复；误判恢复后从恢复日重新累积，**不回填**历史。

---

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 仓库改名/转移 | 跟随 GitHub redirect 更新 owner/repo，**slug 保持不变**（稳定标识）；`repo_history` 记录旧名 |
| 同仓多 harness | 一条记录，不重复计数 |
| 名额不足 500 | 保持空缺，页面显示「收录中 N/500」 |
| 同一作者批量提交多仓 | 合并为一次评审，防刷榜；同一作者在册上限 10 条 |
| 目录站收录但 GitHub 无 star | 不满足规模门槛，进候选池 |
| 榜单页历史链接 | 退出后仍可访问详情页（标注已移出） |

## 9. 实现约定（Phase 1 落库）

```sql
ALTER TABLE plugins ADD COLUMN status TEXT NOT NULL DEFAULT 'active';  -- active|watch|exited
ALTER TABLE plugins ADD COLUMN added_at DATE;        -- 首个有效快照日
ALTER TABLE plugins ADD COLUMN exited_at DATE;
ALTER TABLE plugins ADD COLUMN exit_reason TEXT;     -- E1..E6 / manual
ALTER TABLE plugins ADD COLUMN entry_reason TEXT;    -- 收录理由（人工）
CREATE TABLE repo_history (
    plugin_id INTEGER NOT NULL,
    owner TEXT NOT NULL,
    repo TEXT NOT NULL,
    changed_at DATETIME NOT NULL,
    PRIMARY KEY (plugin_id, owner, repo)
);
```

- seed 文件 `note` 字段保留收录理由；`inclusion_rule` 指向本文。
- CLI：`seed-add`、`seed-remove --reason`、`seed-watch`、`changelog` 子命令。
- 校验器新增：在册数 ≤ 500、观察区 ≤ 30、slug 唯一、退出原因必填。
