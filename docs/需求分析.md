- 版本：v1.2（2026-11-19）
- 变更：新增 [收录规则](收录规则.md)（进入/退出/挑战者替换）；登录方式确定为仅 GitHub；部署前提为海外服务器
- 状态：待评审
- 上游文档：[设计文档.md](../设计文档.md)（产品口径）
- 本文定位：把产品想法落成可开发、可验收的工程需求；**不含业务代码**。

**与设计文档的关键差异**：设计文档 §6 假设「DSH 沙箱内单端口发布、前端产物由后端托管」。现部署前提改为 **2C1G 公网轻量服务器 + 前后端分离**，因此改为：

- 前端：Nginx 托管静态 SPA；
- 后端：独立进程监听 `127.0.0.1:8000`，Nginx 把 `/api` 同域反代过去；
- 采集：GitHub Actions 每日抓取并把快照提交进 git，服务器只拉取与导入。

## 1. 目标与成功指标

**产品目标**：每天抓取 DeepSeek Harness（DSH）插件的 GitHub star（名单来自 awesome-dsh-plugin，约 1.1 万个仓库），产出榜单、曲线、押黑马与推荐位，公网可访问、可长期无人值守运行。

**工程成功指标**：

| 指标 | 目标 |
|---|---|
| 数据完整率 | 连续 7 天快照 `ok=100`，日缺口 0 |
| API 性能 | p95 ≤ 300ms，错误率 < 0.5% |
| 前端体验 | 首页 LCP ≤ 2.5s（4G），JS 首包 ≤ 200KB gzip |
| 可用性 | ≥ 99.5%/月；抓取失败不影响读服务 |
| 资源占用 | 常驻内存 ≤ 600MB（1G 机器留余量），CPU 峰值单核 < 60s |
| 玩法正确性 | 周结算可重放，重复结算 0 差异 |
| 可恢复性 | 从 git 快照重建 DB ≤ 10 分钟且对账一致 |

## 3. 系统架构

### 3.1 部署拓扑（单机）

```
harnesspack.dev → Cloudflare（可选，免费 CDN/WAF）→ Nginx :443
   ├─ /          → /opt/harnesspack/frontend/dist（SPA，try_files → index.html）
   ├─ /assets/*  → 长缓存（1y, immutable）
   ├─ /api/      → 127.0.0.1:8000（uvicorn，单 worker）
   └─ /health    → 直通 API
定时：systemd timer 每日 00:10 UTC → git pull → validate → ingest
旁路：GitHub Actions 每日 00:10 UTC 抓取并提交 data/snapshots/YYYY-MM-DD.json
备份：每日 00:40 sqlite3 .backup + 快照归档 → 对象存储 / 另一台机器
```

**数据来源双轨制**：

- **A 轨（推荐，线上）**：GitHub Actions 跑抓取器 → 快照 JSON 提交进 git → 服务器定时 `git pull` + 导入。
  理由：GitHub token 不落生产机；抓取与线上解耦，抓取失败不影响站点；快照版本化，数据库可全量重建；漏跑可在 Actions 手动补跑。
- **B 轨（兜底/本地）**：服务器或本机直接跑抓取器（需 `GITHUB_TOKEN`），用于 Actions 不可用或需要补数据时。
- 私有仓库用 deploy key；公开仓库（数据本就公开）最省事。

### 3.2 组件边界

| 组件 | 职责 | 明确不做 |
|---|---|---|
| web（React SPA） | 渲染、筛选、图表、押注交互 | 业务计算、直连 GitHub |
| api（FastAPI） | 只读查询、OAuth 登录回调、押注写、参数校验 | 不做抓取，不调外部 API |
| ingest（CLI 进程） | 校验、幂等导入、派生数据、告警 | 不常驻，不对外提供端口 |
| db（SQLite WAL） | 单文件持久化，单写者 | 不存日志/大对象 |
| nginx | TLS、压缩、静态、反代、限流、安全头 | 不做业务 |

不引入 Redis、消息队列、K8s：1G 内存下这些是负担而非收益。

### 3.3 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite + Tailwind + uPlot + TanStack Query + React Router | uPlot 轻（gzip ~40KB）且图表性能好；TanStack Query 管缓存/重试；不做 SSR，SEO 用预渲染兜底 |
| 后端 | **FastAPI + Pydantic v2 + uvicorn 单 worker + SQLite** | 现有采集/校验脚本已是 Python，可直接复用；统计类需求友好；1G 下 RSS 约 120–180MB 可接受；自带 OpenAPI 便于开放 API |
| 认证 | GitHub OAuth 2.0（授权码流）+ 服务端 `sessions` 表 + httpOnly cookie | 无密码、可撤销、不依赖 Redis；后续可加 Google / 邮箱登录 |
| 部署 | Ubuntu LTS + Nginx + systemd + Python 3.12 venv | 不强制 Docker（省内存）；如已用 Docker，`mem_limit: 512m` |
| 监控 | `/health` + journald + UptimeRobot（免费） | 够用、零成本 |
| 构建 | 前端在本地/CI 构建，服务器只放 dist | 1G 机器跑 `vite build` 有 OOM 风险 |

**后端备选与切换条件**：

- Node 22 + Fastify + better-sqlite3：全栈 TS、类型共享、RSS ~80MB；若更看重「一种语言」选它。
- Go + chi + modernc/sqlite：RSS ~30MB、单二进制，最省资源；开发迭代慢，适合后续重构。
- **决策：MVP 用 FastAPI**；若 RSS 持续 > 300MB 或并发超预期，再迁 Go。

### 3.4 数据流与不变量

```
GitHub REST → fetcher → data/snapshots/YYYY-MM-DD.json（git）
  → 服务器 git pull → validate（硬错误则中止并告警）
  → ingest（幂等 UPSERT：plugins / stars / fetch_runs）
  → API（窗口函数实时算榜单）→ React
```

**不变量**：

1. 快照只追加，永不修改历史日；同日重跑幂等。
2. 时间口径一律 UTC；抓取日即数据日。
3. 数据库可从 git 中的快照全量重建（`rebuild`），产物可对账。
4. 失败必须留痕，绝不伪造或插值数据。

### 3.5 资源预算（2C1G）

| 项 | 估算 | 说明 |
|---|---|---|
| 内存 | Nginx 20MB + uvicorn 180MB + SQLite cache 64MB + OS/其它 250MB ≈ 510MB | 加 1–2GB swap 兜底；监控 RSS，> 400MB 告警 |
| CPU | 日常 < 5%；GraphQL 批量约 120 请求，2–4 分钟 | 定时任务放在 00:10 UTC 低峰 |
| 磁盘 | 代码+venv 300MB；DB < 100MB/年；快照 ~1MB/天 | 40GB 盘 3 年无压力 |
| 带宽 | 2000 PV/天 × ~300KB ≈ 600MB/天 ≈ 18GB/月 | 静态资产走 Cloudflare 可省 ~70% |

### 3.6 可用性与降级

| 故障 | 行为 |
|---|---|
| 当日抓取失败 | 保留旧数据；页面显示 `asOf` +「数据更新延迟」；连续 2 天失败告警 |
| 快照缺口 | validate 报告缺口；曲线按真实点绘制，不插值；榜单用最近完整日 |
| DB 损坏 | 从 git 快照 `rebuild`，目标 10 分钟内恢复 |
| 流量超预期 | Nginx 静态 + ETag + Cloudflare；单机可撑日 PV 1 万，再高才考虑拆分 |
| API 进程退出 | systemd `Restart=always`；前端对 5xx 显示重试态 |

### 3.7 安全

- 全站 HTTPS、HSTS；CSP 白名单（self + 静态 CDN）。
- 登录：GitHub OAuth 2.0 授权码流，回调 `/api/v1/auth/github/callback`；随机 `state` 一次性校验防 CSRF；scope 最小化（`read:user`，不申请仓库权限）。
- 会话：服务端 `sessions` 表，token 32B 随机、只存 hash；httpOnly + Secure + SameSite=Lax cookie；30 天滑动过期；退出/注销即时失效。
- 授权：写接口（押注、改昵称、注销）必须登录，未登录返回 401；只读接口公开。
- 限流：登录回调 10 req/min/IP；押注 20 req/min/账号；Nginx `limit_req` 兜底。
- 隐私：只存 GitHub 公开资料、昵称、押注与积分；不存密码；支持注销并在 30 天内清除；日志脱敏（不落 IP 明文、不落 cookie）。
- 无公网管理接口；运营操作全部 SSH + CLI。
- 依赖审计（pip-audit / npm audit）；GitHub token 与 OAuth secret 只存 Actions Secrets / 服务器 EnvironmentFile（600 权限）。

### 3.8 发布与运维

- CI：pytest + vitest + 数据校验 + 前端构建；产物为 dist + 后端代码包。
- 发布：rsync dist → `/var/www`；`systemctl restart harnesspack-api`；migration CLI；保留上一版 dist 与 DB 备份以便回滚。
- 例行：每日 health 检查（快照日期滞后 > 36h 告警）、磁盘/内存巡检；每月一次备份恢复演练。

### 4.6 押注与积分（账号体系上线后开启；建议先只读 1 周）

- **FR-B1** 周期：ISO 周，UTC 周一 00:00 开、周日 23:59 关；结算在周一抓取完成后执行。
- **FR-B2** 下注：每个账号每周 3 注、每注 1 个插件、同周不可重复；仅可押当周池内插件；新收录满 7 天方可押。

- **FR-B4** 神射手榜：总积分、命中率；展示账号昵称与头像。
- **FR-B5** 防刷：账号 + IP 限流；同 IP 每周新增账号上限（如 5）；注册回调冷却。
- **FR-B6 P2** 徽章：伯乐 / 预言家 / 星探 / 老炮 / 续航观察员。

## 6. MVP 范围与验收

**Phase 0 数据地基**：种子 100、抓取器、校验器、Actions、连续 7 天快照。
验收：validate 0 错误；连续 7 天 `ok=100`；`rebuild` 对账一致。

**Phase 1 公开只读**：竞速/增速/总榜/新秀、首页、榜单页、详情、赞助位、`/about`。
验收：全量详情页可访问且无 500；空态文案正确；API p95 < 300ms；移动端通过；HTTPS 单域名；SEO 基础项齐全。

**Phase 2 玩法**：GitHub OAuth 账号体系、押注、积分、周结算、神射手榜、首批徽章、分享。
验收：结算重放 0 差异；UTC 周一 00:00 与 23:59 边界正确；同账号重复下注幂等；未登录调用押注接口返回 401。

**Phase 3 商业化**：推荐位售卖、插件 PK、开放 API 配额。

**明确不做（MVP）**：全量插件、邮箱+密码注册、短信登录、付费订阅、实时抓取、移动 App、多语言。

## 7. 关键决策记录（ADR 摘要）

1. **D1 前后端分离但同域**：Nginx 同域反代 `/api`，不做跨域 CORS，避免 cookie 与安全配置复杂化。
2. **D2 后端 FastAPI**：复用现有 Python 管线，1G 内存可承受；TS 全栈作为备选。
3. **D3 快照进 git，服务器只拉取**：token 不落生产机、抓取与线上解耦、可重建。
4. **D4 SQLite + 单 worker，不引入 Redis/MQ**。
5. **D5 前端本地/CI 构建**，服务器只放静态产物。
6. **D6 榜单实时计算**（窗口函数），必要时再物化缓存。
7. **D7 账号体系：GitHub OAuth 为主，无密码**：目标用户是开发者，GitHub 账号天然适配；OAuth 免去密码存储与找回流程；Google / 邮箱登录后续按需扩展。
8. **D8 会话存 SQLite 服务端表**：可撤销、可强制下线，不引入 Redis；万级用户内完全够用。

## 8. 风险与假设

| 风险 | 对策 |
|---|---|
| 2C1G 内存紧张 | 单 worker、SQLite cache 64MB、swap 兜底、RSS > 400MB 告警 |
| GitHub 限流 | Actions 带 token；未认证也可跑；退避 + 失败隔离 |
| 冷启动曲线短 | 连续 7 天才有有效 7 日榜；UI 文案兜底 |
| 国内网络到 GitHub 不稳 | 抓取放 Actions，服务器只 `git pull` |
| 域名备案（若服务器在中国大陆） | 先确认机房与备案；未备案先用海外节点或 IP 访问 |
| 押注合规 | 纯积分、无货币、无提现、限流防刷 |
| 小号刷分 | 账号 + IP 限流；同 IP 每周新增账号 ≤ 5；异常押注模式检测留痕 |
| OAuth 依赖 GitHub 可用性 | 会话校验在本地完成；GitHub 故障只影响新登录，不影响浏览与已登录押注；后续补 Google/邮箱 |
| 账号数据合规 | 只存公开资料 + 昵称；提供注销入口并在 30 天内删除；隐私政策明示 |

**假设**：Ubuntu LTS 且可 SSH/root；域名可解析；**服务器在海外，无需 ICP 备案**；服务器可访问 GitHub（`git pull`），OAuth 回调域名可达。

**已确定**：

1. 品牌：统一为 **HarnessPack**（`harnesspack.dev`）
2. 仓库：**公开** GitHub 仓库（待推送）
3. 部署：默认不用 Docker，Nginx + systemd 直装；由 agent 代配，待提供 2c1g 服务器 SSH
4. Phase 1 保持纯只读，账号 + 押注放 Phase 2
5. 界面语言：中文优先
6. API：首版只读公开，暂不开放写接口与第三方 CORS

**待确认**：

1. DNS：`harnesspack.dev` 的 A/AAAA 记录指向服务器 IP（当前无解析）；证书用 Let's Encrypt
2. 服务器 OS 与 sudo 权限（默认 Ubuntu 22.04+，SSH 用户需可 sudo）
3. 告警渠道（默认 GitHub Actions 失败邮件 + 服务器 cron 失败日志）
4. 第三方 API 使用条款（Phase 3 再定）
